# Prior-art review: deep-zoom rendering in Fractalia

Search date: **12 November 2026**. This evidence log accompanies the [technical report](fractalia-deep-zoom-rendering.pdf) and evaluates scientific and implementation novelty against the public material retrieved during the review.

## Findings

**The central numerical techniques are established.** Reference-orbit perturbation, series prefixes, rebasing, folded and hybrid perturbation, table-based transcendental evaluation, double-double arithmetic, and adaptive region rendering all have relevant antecedents. The strongest software precedent for recipe specialization is Fraktaler 3. The strongest precedent for the particular stateful and rational families is Charlie Deck's WebGPU renderer, which explicitly describes scaled perturbation recurrences for Phoenix, Nova, and Magnet.

**Fractalia contributes a concrete integration and an engine-specific evaluation.** Its step vocabulary, per-step Julia and periodic Drift, specialization and fallback policies, full-catalog operation inventory, and archived views form an inspectable technical result. The cost ratios follow from this implementation's guard precision, precision thresholds, and term-selection rules. They are not general complexity laws or measurements of a competing renderer.

**Potential follow-up work is narrower than “we perturb Phoenix or Magnet.”** We did not verify a public implementation of the exact eight-step Phoenix error acceptance policy, the same pole-aware local acceptance conditions for rational steps, or a forced Lyapunov reference path that checks the sign of the error interval in the same way. Standard matrix products, the quotient rule, and logistic-map differences are not themselves novel. The exact policies are candidates for a controlled study, not established priority claims.

## Search and screening method

The search used general web indexes, domain-restricted queries against arXiv, ACM, IEEE Xplore and mathematical indexes, and direct inspection of publisher pages, author-hosted articles, project manuals, source files and reference links. It retained primary articles, original technical notes, public code, and first-party documentation as evidence. Secondary summaries and search snippets were used to find candidates, not to infer algorithms. For source repositories, a result was classified as **catalog only** unless a first-party source described the relevant route; separate files for a fractal and a perturbation kernel did not by themselves establish that the two were connected.

Representative query groups, including searches with no equivalent method-level match:

| Group | Example queries and variants | Screening objective |
| --- | --- | --- |
| Quadratic perturbation | `SuperFractalThing Maths perturbation series approximation`; `Khashin fast calculation Mandelbrot infinite resolution`; `Mandelbrot perturbation series approximation rebasing glitch` | Identify original or author-maintained derivations. |
| Hybrid compilation | `fractal deep zoom hybrid perturbation formula sequence loops`; `Fraktaler 3 hybrid opcodes BLA fold`; `Kalles Fraktaler formula XML hybrid`; `Ultra Fractal perturbation equations custom formula` | Distinguish ordered recipes, real Jacobians, and formula-specific authoring. |
| Browser and multiprecision backends | `browser WebGPU high precision reference orbit arbitrary precision deep zoom`; `FractalShark perturbation`; `Fractall bytecode perturbation double double` | Avoid claiming a first web implementation or a first multiprecision fallback. |
| Rational maps | `Magnet perturbation deep zoom fractal`; `Newton fractal rational perturbation theory`; `Nova Magnet WebGPU perturbation`; `Fractal Zoomer supportsPerturbation Magnet Nova` | Locate actual rational difference paths and separate them from direct solvers. |
| Delayed dynamics | `Phoenix memory perturbation reference orbit`; `Phoenix fractal perturbation transfer matrix`; `stateful fractal Phoenix Manowar rebasing` | Check reference differencing and whether the same correlated error policy is described. |
| Transcendentals and Drift | `complex sine exponential Julia perturbation deep zoom`; `exponential Julia reference orbit Taylor`; `fractal parameter drift periodically driven Julia perturbation`; searches for distinctive preset names | Look for direct comparisons with Sine/Exp and per-step time dependence; the original screenshot application could not be identified from the names alone. |
| Lyapunov | `Lyapunov fractal logistic periodic forcing Markus Hess`; `Lyapunov fractal arbitrary precision source`; `Lyapunov fractal logistic parameter delta reference orbit renderer` | Separate the original observable, arbitrary-precision evaluation, and the specific sign-aware reference policy. |
| Arithmetic | `Johansson medium-precision elementary functions table reduction`; `Tang table-driven exponential`; `Brent multiprecision elementary functions`; `Dekker floating-point precision` | Attribute the standard arithmetic ideas and avoid equating model weights with BigInt timings. |
| Enclosures and subdivision | `Arb midpoint radius interval arithmetic`; `Berz Makino Taylor models wrapping effect`; `Mariani Silver rectangle Mandelbrot original`; `Mandelbrot interval region rendering` | Compare decision bounds, formal enclosure arithmetic, and geometric filling. |
| Observables and benchmarks | `smooth escape iteration count Vepstas`; `Newton orbit traps`; `ring squared radius orbit trap`; `fractal deep zoom benchmark BigInt operation count` | Attribute observables and check what competing performance reports measure. |

Name-only searches were noisy. No priority inference was drawn from a missing keyword match. Some older forum threads and publisher full texts were not accessible; public code snapshots can change, and no proprietary binaries were reverse-engineered. No patent database or nonpublic archive was searched. The result is a broad technical scoping review, not a registered systematic review.

## Claim boundaries

| Claim | Evidence | Appropriate status |
| --- | --- | --- |
| The engine specializes its evaluation by recipe and maintains local fallbacks. | [Worker routing](../dist/worker.js), [Studio evaluator](../dist/studio-perturbation.js), [direct evaluator](../dist/precise-formulas.js) | Verified for this checkout. It does not establish priority (E02–E07). |
| The work ratios are a result of the code and the defined counting model. | [Cost script](../scripts/fractal-cost-model.mjs), Appendix A, [fixed-point code](../dist/fixed-point.js) | Reproducible and engine-specific. The model excludes routing, actual orbit lengths, and browser timings. |
| Selected historical views improved without class changes. | [Raw comparisons](data/fractalia-render-optimizations.json) | Descriptive historical result. Controls differ between rows; it is not a single-factor ablation or a cross-renderer performance claim. |
| The exact Phoenix, rational and Lyapunov acceptance policies might warrant further research. | Local code and the scoped negative result against E02–E10 | Candidate contribution. No verified priority, general correctness certificate, or proof of comparative speed. |

To turn the last claim into a stronger study, first implement an independent multiprecision/ball oracle for matched seeds and stopping rules. Compare each policy with the same engine with only that policy disabled, then compare external engines only where formulas, starting states, bailout and scalar observables match. Publish the fraction of rejected fast pixels, per-pixel iteration distributions, class and scalar errors, resource costs, repeated timings and a pinned comparator version. This would distinguish an interesting code design from an empirically supported numerical contribution.
